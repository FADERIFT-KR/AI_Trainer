## 2. 오류 분류 모델 단순화 검토

현재 구조는 1차로 정상/비정상을 가르고, 비정상만 MT-ST-GCN에 넣어 3개 오류 클래스로 분류한다.
이 모델의 Output Head가 두 개인데, 실제 클래스를 보면 정보가 겹친다.

| Head | 클래스 |
|---|---|
| 오류 종류 | 발뒤꿈치오류 / 엉덩이하방오류 / 고관절오류 |
| 문제 부위 | 발목·발 / 무릎 / 고관절 / 몸통 |

발뒤꿈치오류→발목·발, 고관절오류→고관절로 사실상 대응되어 부위 Head가 독립적인 정보를
거의 주지 않는다. 검토 방향은 두 가지다.

- 부위 Head를 없애고 오류 종류 분류에만 집중
- 더 단순하게, 오류 클래스 3개 각각에 대해 OK/NOT을 판단하는 구조

동영상을 그대로 Input으로 넣으면 모델이 무거워지므로 Input/Output을 최대한 단순하게 가져간다.
단, 단순화만 보지 말고 **향후 오류 클래스가 추가될 때의 확장성**도 함께 확인해야 한다.
조교님이 주신 관련 문서를 다시 확인할 것.

## 3. 사용자 피드백 방식

역할을 나눈다.

- **AI(모델)** — 오류 종류 분류
- **DTW** — 구체적인 문제 부위 산출

문제 부위는 별도 Head로 예측하지 않고 DTW 결과를 쓴다. 관절별 기준 이탈값을 계산해
문제가 큰 부위 4개를 뽑아 사용자에게 보여준다.

> 관절별 이탈값 계산은 `ai_trainer/squat/joint_feedback.py`에 이미 있다. 상위 4개 추출만 추가하면 된다.

## 4. F Function

현재 비교 방식은 맞다. 추가로 **MediaPipe 단독 성능을 정량 수치로 산출**해 비교할 것.

> 이 기능은 구현되어 있다(`ai_trainer/squat/metric_check.py`). AI Hub 원천 영상을 입력으로
> 넣고 같은 rep의 3D 정답 CSV와 1:1 대조해 시점별 좌표 매칭율을 낸다.
> 실측(정상/초급/CB01 rep1, 허용오차 100mm): 정면 50.7% / 사선 74.1% / 측면 65.4%.
> 남은 일은 여러 배우·클래스로 돌려 대표 수치를 문서로 정리하는 것.

## 5. G Function

중요한 항목이나 현재 사전 자료가 부족하다. 조교님 개입·논의가 필요하다.
기존 자료를 그대로 따라가기보다 새로운 접근 가능성도 함께 검토한다.

## 6. Agent 방향

Agent가 기존 문서 내용에 지나치게 종속되지 않도록 설계한다. 사전 정보를 과하게 주지 않고
기존 방식과 다른 해결 경로를 스스로 탐색할 수 있게 구성하며, 완전히 새로운 접근법을
제안할 가능성도 열어 둔다. 이것 자체를 Agent 활용 방법 중 하나로 검토한다.
